AgStatus

Privacy Policy

Last updated: October 19, 2026

AgStatus is an open-source status board for coding agents such as Claude Code and OpenAI Codex. This policy covers the AgStatus iOS app and the hosted server at agstatus.online, operated by the project maintainer. The repository also contains an Android client, which is not published to any store; where its behaviour differs from the iOS app, this policy says so.

The short version. There are no accounts and no tracking. The server stores only the small status updates your own machine sends it, stops serving them automatically after 24 hours, and you can delete everything at any time. Deleted records are flagged as deleted rather than erased on the spot — see Retention and deletion.

What the server stores

When you set up the hooks (curl -fsSL https://agstatus.online/install.sh | sh, or irm https://agstatus.online/install.ps1 | iex on Windows), your machine sends the server a small update each time an agent changes what it is doing:

FieldExampleNotes
Session id9f3c…Generated by your coding tool
Namemy-repo or Fix the login bugA Claude session's title when it has one, otherwise the folder name pinned at the session's first event
Projectmy-repoThe folder name the session is working in (for a Claude worktree, its repository's)
StatuscodingOne of six fixed words
Messagenpm testA short activity line, truncated
AgentclaudeWhich coding tool the session belongs to
Timestamps—When each change happened, for the session timeline

By default the message can include a truncated command line (up to 120 characters) so the board is useful at a glance.

A Claude Code session's name can be its title — the one the Claude desktop app gives every session, or one you set with /rename. That title is generated from your prompts, so it can describe what you are working on in close to your own words. The hook reads it from the session's transcript on your machine and sends only the title itself, as the card's name. The conversation in that transcript stays on your machine; the one other thing taken from these files is the token totals described under Plan usage, with the folder names, session ids and dates they are filed under.

If you would rather not send command text or titles, run the installer with --minimal — messages then contain only tool names, such as "Bash", and every card is named after its folder instead of its title. It is the same switch as AGSTATUS_DETAIL=off, and re-running the installer without the flag removes it.

A board is identified only by an unguessable random token in its URL. Anyone who has that URL can view the board, so treat it like a password.

Pairing an app to a board

Connecting a phone to a board can be done by scanning a QR code, which carries the board URL straight from one screen to the other and involves the server only as the thing being connected to. The alternative is a short pairing code, for when the two screens are not side by side. A pairing code is minted by the server and held there, mapped to your board's token, for 15 minutes; it can be claimed once, and claiming it deletes it. Codes that are never claimed are swept away when they expire. Nothing else about the pairing is recorded — not which device claimed a code, and not when.

Plan usage

The hook can also report how much of your plan's rate limits you have used, so the board can show limit bars. The credentials used to look this up are read on your own machine and never sent to the server — only the resulting percentages and reset times are. Set AGSTATUS_USAGE=off to turn this off entirely.

To chart how usage moves over time, the server keeps each reported percentage rather than only the newest one, and the hook additionally reports token totals per project per day and per session — a project folder name or a session id, a date, and a number of tokens, read from your coding tool's own local logs (for Claude Code, its session transcripts). None of these reports carries prompts, code, file contents or conversation. The project folder name is the folder each session worked in — usually the one its card shows, but for a Claude worktree it is the worktree's own folder, where the card shows the repository instead. AGSTATUS_USAGE=off disables this too.

Focus (optional)

Focus — tapping a session on the board to bring its terminal to the front on the machine running it — is installed by default on macOS by the install command above; --no-focus skips it, and it is never installed on Linux or Windows. If Focus is on for a machine (the installer, agstatus listener install, or "focus": true in ~/.agstatus.json), status updates from coding agents on that machine additionally include: a short label you chose for the machine (default "Mac"), a random identifier specific to this board and this machine, and the name and kind of the app the session is running in (for example "agterm, terminal"). The listener keeps a connection open to your board so it can receive taps; it sends nothing but the acknowledgement of a tap. Nothing about your files, folders, terminal, or environment leaves the machine — those details stay in a local file only the listener reads. Turning Focus off stops any further labels being sent; labels already on your board stay there. Machines with Focus off send exactly what the table above lists.

Those local records are not deleted by turning Focus off or by uninstalling the listener — a plain uninstall leaves them in place and says so on screen. agstatus listener uninstall --purge removes them along with the listener's log, and keeps only the machine's own id so a reinstall is the same machine to your board.

What we do not collect

  • No accounts, email addresses, or passwords.
  • No analytics, advertising identifiers, or third-party SDKs.
  • No source code, file contents, or agent conversations.
  • No credentials or API keys of any kind.
  • No web fonts, scripts or images loaded from anyone else's server — every page here serves its own, so viewing a board tells no third party that you did.

Push notifications

Push is iOS only; the Android app has no push and contacts no notification service. If you turn on notifications in the iOS app, they are delivered through Apple's push service (APNs). A notification contains only the session name and its short status message — the same text your hook already sent to your board. Your device's push token is stored with your board and is removed when you turn notifications off, when the token expires, or when the board is deleted.

What the app stores on your device

The iOS app keeps your board's URL and token in the iOS Keychain on your device. It makes network requests only to the board server you configure. Demo mode runs entirely on-device and sends nothing anywhere. The app requests camera access only when you choose to scan a setup QR code. The frames are decoded on the device to read the URL out of the code; no image is stored, and none is transmitted anywhere. The camera is used for nothing else.

The Android client in the repository behaves the same way, with one difference worth stating: it keeps the URL and token in an encrypted preferences file, and if that file cannot be opened — a corrupted keyset, which can only be discarded — it retries once and then falls back to ordinary app-private preferences rather than refusing to launch. The data stays inside the app's private storage either way.

Retention and deletion

  • Sessions stop being shown or served automatically 24 hours after their last update.
  • Plan-usage history and the per-project token totals are kept for 90 days. The per-session totals behind the number on a card are kept for 7 days after their last report — a card cannot outlive that anyway.
  • Boards untouched for 60 days are removed from the service along with all their data — flagged as deleted rather than erased, as below.
  • You can delete a board and everything in it at any time, from the app (Settings → "Delete board") or with one request: curl -X DELETE https://agstatus.online/w/<token>

Deleting removes data from the service immediately: it stops being served, shown, or returned by the API, on every device. It does not erase it. Records are flagged as deleted and the rows stay in the database that backs the service. The self-hosting guide documents this, and how an operator of their own instance purges those rows for good.

Self-hosting

AgStatus is open source under the MIT license. You can run the entire server yourself, in which case no data reaches the hosted instance at all. See the self-hosting guide.

Children

AgStatus is a developer tool and is not directed at children under 13.
