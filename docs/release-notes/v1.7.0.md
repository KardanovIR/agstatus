1.7.0 puts subagents on the board and groups the board by project, on the
web, iOS and Android. A session's running subagents are rows on its card,
each saying what it was asked to do, what it is doing and its state, where
until now their tool calls took turns on the session's one line. The board is
sorted into a section per project, the folder each session started in, which
the server works out and keeps for the session's life; the agents keep their
heads, with their plan limits and session counts, and every card wears its
agent's mark. The alarm leaves the heads for one needs-you bar along the
bottom edge, which names a blocked session and brings its card into view.
AgStatus also has a new icon, one mark on every platform.
The web and the server go out first. iOS 1.7.0 (build 8) follows when App
Review approves it, and Android 1.7.0 goes to Google Play, the app's first
release there, starting with a closed test. The hook and the installer
change too: re-run the installer on each machine, or update the plugin, to
see subagent rows. The release also carries the web fixes that have been
live on agstatus.online since November 7, and a fix for a stall in the usage
history that 1.6.5's server has.

## Subagents on the card

A subagent is anything that runs under a session with an id of its own: an
Agent-tool subagent (foreground, background or nested), a dynamic-workflow
agent, a Codex sub-agent, a teammate, a `/fork`. Until 1.7.0 their tool
calls landed on the session's line, a post apiece, so ten subagents running
in parallel took turns overwriting it and the session's own reading was lost.
Now the line stays the session's, and each running subagent is a row on its
card: what it was asked to do, what it is doing, and its state's mark and
word. A card lists up to three rows on the web and an iPad, two on a phone
and on Android, the oldest first, each keeping its place until it finishes,
with any subagent waiting on approval always among them; a footer counts the
rest, "+7 more · 15 done". The session screen lists them all above the
timeline, and a row opens it at that subagent. At larger text, as at 200%
on a phone, a row gives its task a line of its own and its state and
activity share the next, where the task and the activity had come down to
four letters each.

The server reads the subagents for the card, so the board says what they
mean:

- A subagent waiting on approval turns the card blocked: "Needs approval:
  verify:hook", with "+1" for each other one waiting. It pushes like any
  block, and a second subagent starting to wait pushes again, unless the
  card pushed blocked within the last minute.
- A turn that ends while background subagents or a workflow still run no
  longer reads done: the card shows their busiest state with "3 subagents
  still running", and the 1.7.0 boards draw it as WORKING. As each finishes,
  the card reads "Reading subagent results", and the done push goes out once,
  when the report turn ends.
- A subagent whose launch fails, or whose background task is killed, stays
  listed as failed, with its reason, until the turn is over.
- A row closes when its subagent finishes, and after an hour without news
  (six for one waiting on approval), so a lost post leaves nothing behind for
  long.

In detail mode a row's label is the task description the launch carried, a
workflow's label for its agent, or a Codex sub-agent's nickname; in minimal
mode it is "Subagent 1", "Subagent 2", and no label is read. A subagent is
posted when it starts, when its status class changes and when it finishes,
and while its class holds, what it is doing at most once a minute: about four
posts a subagent, where its tool calls made some 22. Its id leaves the
machine only as a one-way hash, and what it hands back never leaves it. To
tell a subagent's later events from its first, the hook keeps a few small
files on the machine, in a directory only you can read under the system's
temporary folder, which go when the session ends or after a day.

A 1.6.5 app, or a web page from before the deploy, gets the server's
reading and no rows: "Needs approval: verify:hook", "Testing · 3 subagents
still running". A machine with the new hook but not its new registrations,
or with Codex's new entries not yet trusted, reports subagents as before, on
the session's line, and can leave no row behind.

The design and its rules are in
[the subtasks spec](https://github.com/KardanovIR/agstatus/blob/v1.7.0/docs/design/subtasks.md).

## The board grouped by project

**What a project is.** The folder a session started in. The hook already
sends the folder a session is working in; the server now keeps the first
usable one it hears for each session as `homeProject`, for the session's
life, so a session that runs `cd ios` keeps its card where it was, and the
card adds "in ios". A card dismissed, cleared or pushed out by the 50-card
cap comes back to its own section if its session posts again within a day of
its last post, unless the server restarted in between. A session with no
usable folder (one started at `/`, a Codex scratch folder, a folder named
with white space alone, a raw post with a blank folder) waits in **No
project**, and moves once, when a real folder arrives. With the Node hook a
Claude worktree counts as its repository. Nothing is reinstalled for any of
this: the server works it out from what the hook sent.

**Sections.** Each project has a label, its folder's name and "3 sessions",
with its cards under it. The sections run in name order, the names compared
ignoring case and then exactly (`AgStatus` before `agstatus`), with No project
last, and they never reorder because one got busy. A label is not a control
and has no colour. Where the line is short the count goes first, then the
name is cut in the middle. A label sticks while its cards scroll under it on
a phone, on Android and on the web; on an iPad it scrolls with its section.

**The agents' heads.** Plan limits belong to an agent's account, so they stay
with the agents. Every agent with sessions on the board has a head with its
mark, its name, its session count where it fits, and its limits. On the web
and Android each usage block is that head: it gains the count ("Claude 7
sessions"), and an agent that reports no plan limits, which had no block, now
has one that says "No plan limits reported". On iOS the heads lose their
alarm and their blocked edge, so red in a head only ever means a limit.

**Every card wears its agent's mark.** Claude's and Codex's sessions share
sections now, so the meta line starts with the agent's neutral mark: an
asterisk for Claude, a hexagon for Codex, a diamond for any other agent.
The web's and Android's bordered CLAUDE and CODEX boxes are gone. A screen
reader hears a card as "Claude, Fix the login redirect", or "Codex" alone
where the session is named after its agent.

**Cards keep their place on the web.** The web board re-sorted every card by
its last update on each event, so the card you were reading jumped to the
top whenever its agent ran a tool. A new session now goes on top of its
section and every other card stays where it is, blocked ones included, as on
iOS and Android. The needs-you bar is the way to a blocked card.

The layout's rules, and the owner's decisions behind them, are in
[the project sections spec](https://github.com/KardanovIR/agstatus/blob/v1.7.0/docs/design/project-sections.md).

## The needs-you bar

While at least one session is blocked, one bar along the bottom edge says so,
on every client: "(!) 2 BLOCKED · Fix the login redirect · in acme-api ·
Show". The web and Android had no alarm before it. Its ground and top edge
are a blocked card's own, so at rest it reads as a band from the corner of the
eye: its ground is 1.27:1 against the page (1.28:1 on the web), where a
card's neutral ground is 1.07:1, and every word on it clears WCAG AA, the red
ones at 4.82:1 (4.80:1 on the web). It is one line on a wide board, giving up
the word BLOCKED, then the project, then the end of the name as room runs
out, and two lines on an upright phone. For a session in No project it names
the agent instead.

Pressing it brings the card it names into view, under its label, with a
neutral ring for two seconds, and moves keyboard, VoiceOver or TalkBack focus
to it. With more than one blocked, the bar then names the next in reading
order and says Next. When another session blocks while the bar shows, the
bar comes in from the bottom edge again, once, with the new count, so the
news is more than a changed digit. It never pulses: no beat for an answer,
for one block in place of another, or for blocks that were already there
when the board was opened, and blocks that land within half a second make
one beat. It moves only while the board is in front of the reader, and
under reduced motion it appears and goes in place.

A new block is also said, in one sentence on every client: "Fix the login
redirect, in acme-api, needs you", "Codex needs you" where there is no
place, or "2 sessions need you" for blocks within half a second. Only a
session's move into blocked is said, at most once a minute per session, never
for blocks a page load, a reconnect or a refresh finds. The web says it
through a polite live region; Android through TalkBack, on every screen while
the app is in front; iOS through VoiceOver while push is off, as in 1.6.5.

On the web the bar comes after the usage blocks and before the cards for the
keyboard and screen readers, and keyboard focus is never left under it or
under a stuck label. On Android a keyboard's focus on the bar is a 2dp ring in
the accent inside it, 7.41:1 against its ground, so the red word keeps its
4.82:1, where Material's focus layer would take it to 3.95:1. On iOS
VoiceOver reaches the bar before the cards, Magic Tap presses it from
anywhere on the board while it shows, and Voice Control answers to its verb,
"Show" or "Next".

## A new icon

AgStatus has one mark on every platform, where it had five that disagreed:
the iOS icon's glowing tiles, Android's flat ones, the web's green dot, and a
pulse line and a chart on the two welcome screens. Three strips sit on the
dark ground: two are unlit, and the one that needs you is lit and slid out of
line, the way an air traffic controller pulls out the strip of the one flight
that needs action. It is the iOS app icon, with dark and tinted versions for
iOS 18 and later; Android's launcher icon, with a one-colour layer for themed
icons; the welcome screen on both; the Play icon and feature graphic; and the
tab icon of every page, the board's included, which had none.

## The server

**Subagents.** Each session's subagent state is kept beside the parent's own
reading, which a subagent's post never overwrites, and goes out as an optional
`subtasks` object on the session. A session without subagents is sent exactly
as before, key order included, plus `homeProject`. The state is bounded: 48
live rows a session, 256 a board, 8 KB of `subtasks` per session, and one
frame per 250 ms per session from subagent posts. It survives a restart in a
new column.

**Names in one Unicode form.** A folder made in the macOS Finder is often
named decomposed (NFD), and a Linux checkout of it composed (NFC). The server
now keeps and serves every session's `name` and `project` in NFC, so one
folder is one section on every board. A posted value is cut to 512 UTF-16
units before it is composed, then to 120, and a row an older server stored is
composed as it loads.

**A blank name is no name.** A `name` of white space alone counts as omitted,
as an empty one already did: the card keeps the name it had, or is named by
its id.

**The usage history no longer stalls the server.** The usage history sorted a
board's per-project days with a locale's collation, whose cost grows with the
square of a run of combining marks in a name. Measured on Node 20.9 with one
board holding its 5,000 project days named in the worst order, a read held
the server's one thread for 1.1 to 1.8 s, 30 reads at once took 33 to 61 s
to be answered, and other boards' hook posts waited 1.3 s or timed out at
3 s. The server now sorts the usage list and history by UTF-16 code unit: a
read takes 7 to 16 ms, and 30 at once are answered in 0.19 to 0.29 s. Only
the order of rows whose names differ by case, by `-`, `_` or a digit, outside
ASCII or in Unicode form moves.

The server no longer cuts a string through the middle of a surrogate pair.
The 1.6.5 hook cut a prompt at 120 units, sometimes inside an emoji; such a
stored row now loads with U+FFFD in place of the half, and the half is
stripped from new posts.

## The hook and the installer

**New registrations.** For Claude Code, `agstatus init` and the plugin
register `SubagentStart`, `SubagentStop` and `PermissionRequest`,
`PostToolUse` on `Agent`, `Task` and `Workflow` and `PostToolUseFailure` on
`Agent` and `Task`, and `PreToolUse` gains `Agent` and `Workflow`. Every
entry but `SessionEnd` has a 10-second timeout, where Claude Code's default
is 600 s. For Codex, `UserPromptSubmit`, `SubagentStart` and `SubagentStop`
join the four it had. A Codex root prompt now turns its card to planning
with "Processing prompt"; the prompt itself is never sent.

**Fixed on the way:**
- Every subagent launch was dropped: Claude Code renamed the `Task` tool to
  `Agent`, and the hook matched only `Task`. A launch now shows its task on
  the session's line.
- A background subagent's completion, which Claude Code hands the session as
  a prompt of `<task-notification>` blocks, showed on the card as your
  words. It reads "Reading subagent results" now, and finishes the matching
  rows.
- `Stop` said done while background subagents still ran.
- Notifications that ask nobody anything (`auth_success`, `agent_completed`
  and the like) turned cards blocked and pushed.
- A compaction posted idle.
- Host detection read a Codex sub-agent's log as its root's, so Focus could
  raise the wrong window.

**Approvals.** Claude Code's `Notification` does not say which thread is
asking, so the hook notes each `PermissionRequest` and lets the next
notification claim the oldest note, which is how a subagent's prompt reaches
its own row. A prompt nobody can be named for blocks the session, as before.

**Where to trust the Codex hook.** The installer, `agstatus init` and the
docs said to run `/hooks`, which Codex Desktop does not have. They now say
Settings → Hooks in Codex Desktop, and `/hooks` in the Codex CLI.

A CLI test that failed whenever a step took a millisecond no longer does (on
master since November 7).

## The web board

**The usage blocks on a phone** (live since November 7). A block's limit
names ran out of it: at 375px "Current week (all models)" ran under the Codex
block, and at 200% text five names in six ran out and the page was 493px
wide. A name now wraps inside its block, and blocks take a row each once two
across would leave either less than 11em. A narrow block puts each reading
under its limit's name, where a phone held sideways cut five names in six.

**A first-day column keeps its width** (new). In the table of each day's
figures, a window with one reading headed its column with its mark, and the
column was 14px narrower on its first day than after (88.1 against 102.1px).
It is the width it will keep.

**No more "dot" in NVDA** (new). A card's title is described by its state,
and Chrome built that description from the state row's boxes, setting each
apart: "CODING , no update for 14 minutes .", whose detached full stop NVDA
reads as "dot". It is one sentence now, "Coding, no update for 14 minutes.",
and the page draws exactly as before.

**A page the browser kept** (new). The board page names its files with the
release (`?v=1.7.0`, which the server ignores), so a page Back takes from the
cache after a deploy loads its own release's files. A 1.6.5 page kept that
way draws its cards and connects, without the bar, until it is loaded again.

Project labels and the bar grow taller rather than cut letters when a reader
sets their own text spacing (WCAG 1.4.12), and the landing page describes the
board grouped by project, with the needs-you bar. The landing page's demo
button is named by the word it shows, Play or Pause, where it was named
"Resume the demo board" (WCAG 2.5.3).

## iOS

The iPhone and iPad boards are grouped by project, as above. The agents keep
their heads, pinned two across on a phone by 1.6.5's rules; where those do
not fit, the heads become the first rows of the list and scroll away, in
place of 1.6.5's pinned line of names and alarms, which is gone. On an iPad
the agent columns give way to full-width sections with cards two across,
under a full-width strip for each agent, and the bar walks the cards in the
order they are drawn. Split View and large text step down to the phone's
list, as before.

Cards list their running subagents (three rows where the board is two
columns wide, two in the list), the session screen lists every one above the
timeline, and a card whose turn is over while its subagents work reads
WORKING, in coding's colour with a branch mark. A failed row has a mark of its
own. Rows move only for news: a row fades in when it starts, and its state
comes in again when it blocks, unblocks or fails, with none of it under
Reduce Motion.

VoiceOver no longer hears a blocked card again when a refused dismissal puts
it back, nor a block that a pull to refresh brings in.

Try the demo runs a workflow with subagents beside its four sessions, as
Android's demo does: its rows start, finish, fail and wait for approval, a
wait turns the card blocked and puts it on the needs-you bar as on a real
board, and the turn ends, the parent reads the results and the workflow
starts over.

## Android

The Android board is grouped by project under labels that stick, every card
starts its meta line with its agent's mark, and the needs-you bar is the
screen's bottom bar, with TalkBack saying new blocks on every screen while
the app is in front. The usage blocks stay pinned while the list keeps room
under them for a label, the shortest card and the bar, and otherwise lead the
list and scroll away with it, as a phone held sideways or large text needs.
Cards list two running subagents each, and the session screen lists all of
them.

Also: a card swiped away comes back whole when its session posts again,
where it came back as the red Dismiss slab; a card's state glyph grows with
the reader's text, as its word does; and a hook event redraws only the card
it changed.

**Android goes to Google Play.** 1.7.0, versionCode 7, is the app's first
release on Google Play. A personal developer account has to run a closed
test first, with at least 12 testers opted in for 14 days in a row, before
Play takes an application for production access. The listing, the Data
safety and content rating answers and the checklist are in
[distribution/google-play](https://github.com/KardanovIR/agstatus/tree/v1.7.0/distribution/google-play),
and the privacy policy now covers the Android app.

## How it was checked

The root suite, 755 tests with Postgres 16, and the CLI suite, 633, pass on
this release, with `tsc` clean for both. The iOS app builds in Debug and
Release, and Android's 315 unit tests and lint pass. During the release's
verification an upgrade from 1.6.5 and a rollback to it were run against
Postgres 16, and the 1.6.5 iOS app against the 1.7.0 server, in both modes,
with no fault.

The web board ran in headless Chrome 157 and in Mobile Safari on an iOS 26.5
simulator; Firefox was not run. No screen reader was run on the web: what one
is told was read from Chrome's accessibility tree. The Android app ran on an
emulator, where TalkBack's own log showed it saying a new block. The new
icon was checked at every size the systems draw it, in iOS 18's dark and
tinted looks, in iOS 26's six looks through Apple's own renderer (Icon
Composer's ictool in Xcode 26.6), and in Android's launcher masks and themed
icons.

VoiceOver and Full Keyboard Access were not run on a real iPhone or iPad: the
owner waived those device checks for this release. VoiceOver does not run in
the Simulator, so what it is told was checked in the accessibility tree, and
Full Keyboard Access was walked in the Simulator only. The iOS app was tested
on iOS 26.5 only, in the Simulator, not on iOS 17 or 18, though it still
supports iOS 17.0 and later; the bar's motion uses APIs that came with
iOS 17.

## Upgrading

**Your machines.** Re-run the installer on each one:

```bash
curl -fsSL https://agstatus.online/install.sh | sh
```

On Windows it is `irm https://agstatus.online/install.ps1 | iex`. It copies
the new hook and writes the new registrations together, and keeps the
machine's server, `--minimal`, secret and Focus opt-out, as it has since
1.6.4; only `--no-codex` has to be given again. Until a machine is upgraded it
behaves as 1.6.5 did: no subagent rows, and its subagents' tool calls on the
session's line. The project sections and the bar need nothing on your
machines.

**The Claude Code plugin.** Update it from `/plugin`. This time it is needed:
its `hooks.json` gains the subagent events, and they arrive with the plugin.

**Codex.** The upgrade adds `UserPromptSubmit`, `SubagentStart` and
`SubagentStop` under the command Codex already trusts, which has not changed
since 1.4.0. Whether Codex wants entries added that way trusted again is not
known, so the installer says so when it adds them: if Codex lists an AgStatus
entry as untrusted, trust it, in Settings → Hooks in Codex Desktop or with
`/hooks` in the Codex CLI. Until then Codex sub-agents are reported as before,
on their root's line. See
[OpenAI Codex specifics](https://github.com/KardanovIR/agstatus/blob/v1.7.0/docs/hooks.md#openai-codex-specifics).

**iOS.** Update from the App Store once 1.7.0 is through review. Until then
the 1.6.5 app reads the 1.7.0 server as before, grouped by agent, with the
server's reading of a card's subagents in place of rows. Building the app
yourself takes Xcode 26 or later.

**Android.** Testers in the closed test get 1.7.0 from Google Play, and
everyone once Play grants production access; until then it can be built
from the repository.

**Self-hosting.** Back up the database before you upgrade: 1.7.0 adds two
nullable columns to `sessions` at boot, `subtasks` and `home_project`. It
deletes nothing, and rolling back to 1.6.5 loses nothing, though a rollback
and a roll forward can move a card to another section
([docs/self-hosting.md](https://github.com/KardanovIR/agstatus/blob/v1.7.0/docs/self-hosting.md#persistence-postgresql)).
With the bundled Compose Postgres:

```bash
docker compose exec -T postgres pg_dump -U agstatus -d agstatus > agstatus-before-1.7.0.sql
```

Then pull `ghcr.io/kardanovir/agstatus:1.7.0` (also tagged `1.7` and
`latest`) and restart. With the repository's `docker-compose.yml`, `git pull`
and run `docker compose up -d --build` with the `--profile` flags you always
use; the file has not changed since 1.6.4, so no `down` is needed. A browser
tab left open on the board picks up 1.7.0 when it is loaded again. Against a
server older than 1.7.0, the 1.7.0 apps group cards by the folder each
session is in now, so a card moves when its session changes directory, and
draw no subagent rows.

**API changes** ([docs/api.md](https://github.com/KardanovIR/agstatus/blob/v1.7.0/docs/api.md)):
- Every session object, on REST and SSE, gains `homeProject`, worked out by
  the server and never read from a post, and an optional `subtasks` object,
  last, on sessions with subagents.
- The webhook takes `agent` (a subagent's post), `turn` and `unattributed`. A
  malformed `agent` is a `400`; subagent posts share the webhook's 120 a
  minute.
- `name` and `project` are cut to 512 UTF-16 units, composed to NFC, then cut
  to 120, and a `name` of white space alone counts as omitted.
- `/api/usage` lists by `source`, and the usage history by `source` and
  `windowId`, and by `day`, `source` and `project`, compared by UTF-16 code
  unit, never by a locale's collation.
- Every agent with sessions on a board gets its usage block, whether or not
  it reports limits.
