The first release since 1.5.3. There is no 1.6.0: it was prepared and never
tagged, and everything it was going to carry is here. A Claude card is named
after its session now, not after the folder the desktop app made up for it.
Focus on a Claude desktop session tries to open that session — experimental,
because the link it uses is undocumented and has not been opened end to end.
A reinstall no longer leaves Focus switched off. The web board has session
history. Android is on the design system, and the two platforms CI had never
touched are built and tested.

## Cards named after the session, not the folder

The Claude desktop app runs every session in a worktree it names itself, so a
board of desktop sessions was a column of "zealous-jennings-84637b" and its
siblings — a name nobody chose and nobody can navigate by. The app also titles
every session ("Session organization by agent"), and `/rename` titles one in
the CLI; both write that title into the session's transcript. The hook now
reads the end of the transcript (the last 256 KiB, never the whole file) and
names the card after the newest title there. A title once seen is pinned in the
hook's local name map, written `0600`, so an event whose read misses it — one
after a pasted image or a giant tool output — keeps the name; a rename renames
the card. Without a title the card keeps the folder it started in, as before.

**This changes what is sent by default.** A title is generated from your
prompts, so it can describe your work in close to your own words. Minimal mode
(`--minimal`, `AGSTATUS_DETAIL=off`) never sends one — those cards keep their
folder names — and the privacy policy now says so. Codex sessions have no title
the hook reads.

Two smaller changes ride with it:

- **A worktree root reports its repository as `project`.** For a working
  directory that is exactly `<repo>/.claude/worktrees/<name>`, `project` is
  `<repo>`, so a titled card reads "Fix the login bug · in claude-status"
  instead of putting the made-up folder straight back under the title. A
  directory *inside* a worktree keeps its own name. The per-project token
  totals are unchanged and still file a worktree's spend under its folder.
- **Host notices stay out of the activity line.** Claude Code and the desktop
  app inject `<system-reminder>` blocks into the prompt the hook is handed, and
  a card once read "<system-reminder> The user started your suggested
  background task…" — the host talking to the agent, shown as your words.
  They are dropped, and a prompt that was nothing else reads "Processing
  prompt".

`agstatus focus --list` names each session the way its card does: name first,
then "in <project>" when the two differ. The slot a key press reports leads
with the name too, since project-first gave every desktop session in one repo
the same label.

## Focus opens the Claude Desktop session — experimental

Focus and Resume on a Claude desktop session open that session in the app,
through `claude://claude.ai/epitaxy/<id>` with the id the app hands its agent.
Until now the tap only brought the app forward, onto whichever conversation it
last showed. It is **experimental**, and for a plainer reason than most rows:
nothing public documents the link. It is the one the app's own session API
returns as the way to open a session from outside the app, and it has not been
opened end to end.

The listener uses it only when the session's record shows the app itself
started that agent. Everything started inside a desktop session inherits its
id, so a `claude` run from a session's tools would otherwise open its
parent's conversation and report success. An id of any shape but the one the
app uses is dropped. In every such case the app is brought to the front, as
before. The experimental mark appears in the listener's log and
`agstatus listener plan`, not on the board, so an experimental Resume there
reads "Resumed" like any other.

A Resume tap on a desktop session whose agent has gone opens the same link,
and the app carries the conversation on; the listener starts nothing itself.

## A `claude` run from a desktop session's Bash tool brings the app forward

Focus on one answered `unsupported-host`. Its process walk lands first on the
`claude.app` the desktop app bundles and runs its own agent from, and records
that bundle's id, `com.anthropic.claude-code` — which is not an app the
listener knows how to raise, and must never be handed to `open`, because that
would launch the agent binary as an app. Such a session now gets plain
activation of Claude Desktop instead: the app it is actually running inside,
never the link, which it inherits from its parent and which would open the
parent's conversation.

It gets that only when the record says it lives inside the app — the
`claude-desktop` entrypoint, inherited from the desktop session, and, when the
record has one, that session's `__CFBundleIdentifier` — so a `claude.app`
under the same id that is *not* inside Claude Desktop still answers
`unsupported-host` rather than raise an app it has nothing to do with. A
Resume tap on one whose agent has gone brings the app forward, as it did
before.

## A reinstall no longer leaves Focus switched off

`launchctl bootout` returns before a running job has finished exiting, and
launchd keeps the job's label until it has, so the `bootstrap` the installer
ran straight after it could fail — typically `5: Input/output error`. The
installer printed a warning and the listener stayed unloaded until the next
login. That is what the October 5 CLI update did to one machine: every board
showed it offline for Focus for 11 days, until it was loaded by hand.

A reinstall now waits up to 5 s for the old listener to leave launchd, then
tries the bootstrap up to four times, a second apart. If every try fails it
says plainly that the listener is written but not loaded, and prints the
command that loads it; `agstatus listener doctor` prints the same command.
`agstatus listener uninstall --purge` waits the same way, so the old
listener's last log line can no longer land after the log was deleted.

## Session history on the web board

Tapping a card's name on the board opens that session's timeline: every status
change with its message and its time, newest first, at `#session/<id>` so it
survives a reload and a back button. The phone apps have had this since 1.0;
the board you leave open on the second monitor did not. The card's title is a
real button, so the timeline is reachable from the keyboard, and the dismiss and
Focus controls beside it still do only what they say.

## Android looks like the rest of the product

1.5.0 shipped the redesign to iOS and wrote down what it had not reached;
1.5.1 did the web board and the public pages. Android was the last one, and it
was still the palette this project names as its first anti-reference: a
near-black `#0B0D12` with six unmodified Tailwind defaults on it — `blue-500`,
`purple-500`, `amber-500`, `red-500`, `emerald-500`, `gray-500`.

`Theme.kt` is a **transcription** of the iOS table rather than a second
conversion of `tokens.css`. Three clients converting the same OKLCH values
independently is three chances to disagree, and the point of a design system is
that they cannot.

The palette was the easy half. What came with it:

- **The accent.** It was `planning` blue in 27 places — buttons, switches, the
  FAB, every link — with white or `textPrimary` on top of it, measuring 2.72:1
  and 1.9:1. It is `done` green now, because `done` is the state that hands the
  turn back to you, and anything filled with it takes `Theme.onAccent`: 9.41:1,
  where white is 2.05:1.
- **The card's 4dp edge stripe is gone**, replaced by the state tinted across
  the whole surface. That stripe is the most overused device in dashboard UI
  and never reads as intentional, whatever colour it is given — and a large
  tinted area reads from much further away than a 4dp sliver.
- **Nothing glows.** The blocked card carried a 12dp coloured shadow and the
  connection dot a 3dp one. A lit halo is the trading-terminal tell and it is
  exactly wrong in a dark room at 1am, which is when this board gets read.
- **`done` is no longer dimmed.** It was drawn at 0.55 alpha, from when it
  meant "finished, nothing to see". It means the agent is waiting on **you**.
  Only staleness dims a card now.
- **State is no longer carried by hue alone.** Every status has a mark as well
  as a colour, on the card, in the history header and down the timeline — on
  the web board's new timeline too. Roughly 1 in 12 men cannot separate the
  red and green states by colour at all.
- **Nothing pulses.** The status badge animated forever on every active card:
  ambient animation that reported nothing, never stopped, and cost battery to
  keep saying the same thing. The three animations that do report something —
  the meter fill, the self-hosting disclosure, the list reordering — now honour
  the platform's animation scale, which the app ignored everywhere.
- **A meta line**: agent, machine, directory, when. The machine was only ever
  visible inside the Focus button's label, so two sessions of the same project
  on two machines were indistinguishable at a glance. It wraps, which the web
  board had to learn the hard way.
- **The Focus control got quieter.** Filled in the new accent it was the
  loudest thing on the card by a wide margin, and a card with two loudest
  elements has failed the first design principle. It is the same raised surface
  and hairline iOS uses.

Smaller things from the same pass: the pairing code's expiry clock was
`testing` teal and is `limitWarn`; the limit-history chart's series order
disagreed with both other clients; the project-token bar was a two-stop
gradient between two hexes belonging to no token; the launcher icon was eight
more of them; and the demo badge borrowed `coding` purple, which made the
toolbar look like a session in progress.

> **Still not published to any store.** The submission package in
> `distribution/google-play/` is updated — listing copy, screenshots
> recaptured from CI's build, versionCode — but the icon and feature graphic
> still need re-exporting from the new palette, and nothing has been uploaded.

## Two platforms CI had never built

- **Android.** Every release until now shipped an Android client that nothing
  had compiled. It is built, linted, and — this is the part that matters — its
  five unit suites are finally run; the job built the APK and stopped. The
  debug APK is kept as an artifact for fourteen days, because the only machine
  that can build it is the runner: AGP 8.13 needs JDK 17.
- **The Windows installer.** `install.ps1` was parse-checked and never
  executed. It now installs for real on `windows-latest`, as a freshly created
  standard user, against a board built from the checkout — then upgrades over
  itself, and asserts what landed and that it runs. A second job asserts the
  argument guards refuse what they are supposed to refuse.

That second job found one on its first run: `-Bogus x` was answered with the
POSIX-flag message, advice about `--code` versus `-Code` for someone who never
typed a POSIX flag. A value starting with one dash is a misspelled PowerShell
parameter and now gets the list of parameters that exist. Both still refuse
before anything is downloaded.

## Fixes

- **The "·" between a card's facts failed contrast on iOS**, at 1.80:1 — the
  strong-hairline token used as a glyph. It is the same mistake the web audit
  caught at 1.52:1 and fixed on the web only. All three clients draw it in the
  tertiary text colour now, and the token says in all three what it is for.
- **iOS's `AccentColor` asset was still the retired blue.** The app's own
  palette had moved in 1.5; the asset the system tints with had not.
- **On Android, the plan-limit meters drew their track in white at 6%** rather
  than the surface token, so it was a colour belonging to nothing and drifting
  from the thing it was meant to be. It ships with the Android client, which is
  not published yet.

## Upgrading

```bash
curl -fsSL https://agstatus.online/install.sh | sh
```

Same command for a first install and an upgrade, and it keeps the board you
already have. On macOS it reinstalls the Focus listener with this release's
code, so the upgrade itself waits for the old listener properly. A machine that
has shown offline for Focus since an earlier upgrade is loaded again by it;
`agstatus listener doctor` says whether it is.

If you would rather your cards kept their folder names, re-run the installer
with `--minimal`. That also stops command text and prompts being sent.

**The plugin.** An installed Claude Code plugin is pinned to its version
string, and 1.6.0 has been in the plugin's manifest since October 5 with the
previous hook behind it — which is why this is 1.6.1 and not more of 1.6.0.
Update it from `/plugin` inside Claude Code.

No client needs updating for the new names: the name on a card is the hook's
to choose, so the web board, iOS and Android show them as they are. The two iOS
fixes above reach the App Store with the next iOS build, and the Android client
is still not published anywhere.
